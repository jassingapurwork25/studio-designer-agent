# Design and Engineering Handoff

## Workflow
1. Summarize project context and the delivered scope.
2. List routes/screens covered and key decisions.
3. Document tokens, reusable components, states, responsive behavior, content rules and asset requirements.
4. List changed files and important implementation details.
5. Report tests run with exact outcomes; distinguish not run from passed.
6. Record known limitations, follow-up work, and dependencies.
7. Provide acceptance checklist and suggested owner/priority when known.

## Rules
- Do not claim a handoff is complete if assets, responsive specs, states, or implementation notes are missing for the agreed scope.
- Never conceal unresolved issues.
- Keep documentation actionable and concise.
